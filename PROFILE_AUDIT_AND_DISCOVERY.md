# Profile audit and automatic donor discovery

The admin user detail uses the same UnifiedDashboard, patient ID card and medical timeline as the patient profile. It now supplies the existing patient ID, current image, health details and service cities from PostgreSQL. Medical audit endpoints enforce the existing ADMIN/MANAGER roles, validate the selected user and record ownership, and return private/no-store responses. History, attachment previews/downloads and doctor-prescription downloads share the patient read implementation. Audits do not change the patient's read marker or email delivery state. Medical uploads remain patient-owned; the audit presents records in view-only mode.

Both report and patient-prescription forms retain multiple attachments, separate record entries, image previews/zoom, device-camera capture on supported mobile browsers and the existing JPEG/PNG/WebP/PDF limits. Images are processed by Sharp and saved as encrypted WebP bytes in PostgreSQL; PDFs and metadata remain encrypted database records. No new migration or encryption key is required. Never replace the existing medical encryption key.

Public browsing never requests GPS permission automatically. An optional **Use precise location** button requests browser location only when clicked, confirms the country through the existing reverse-geocoding endpoint, and shares the result with the blood/organ views. Denial or an approximate/unavailable reverse response preserves automatic detection. Automatic country detection uses existing proxy country headers first. When unavailable, the existing Geoapify key can resolve the visitor's forwarded public IP through its IP Geolocation API. The request always includes the visitor IP, never the VPS address by omission. Requests are bounded and deduplicated, with a short bounded in-memory cache; IPs and provider responses are not logged or returned to the browser. The client shares one lookup and falls back to timezone/locale when needed. Country choices remain user-correctable and override automatic suggestions.

On the VPS, ensure the reverse proxy overwrites X-Real-IP with the client address (or provides trusted Cloudflare country/IP headers). A missing visitor address or unavailable geolocation service cannot establish an exact country; fallback estimates and user selection remain available. IP geolocation is approximate, especially with VPNs and mobile networks. Provider reference: https://apidocs.geoapify.com/docs/ip-geolocation/.

Discovery searches the selected country and detected city first, then other available cities in the country, then other countries. Coordinates, when available, rank fallback blood/organ results by great-circle distance. Country-only detection uses existing nearby-country prioritisation. Local blood feeds retain newest-registration order. Effective fallback filters are carried into pagination. A visible notice explains expanded locations or donation categories; different groups/categories are never labelled as matches to the requested filter. Network errors do not cause filter broadening, and no synthetic donors are fabricated. If the entire real directory is empty or the database is unavailable, no implementation can honestly show real donor records; existing registration and recovery interfaces remain available.

Validation uses disposable local PostgreSQL databases and synthetic files. It covers profile parity, multipart image uploads for both document types, admin/patient download equality, unauthorized access, cross-patient record IDs, unchanged prescription state, geographical ordering, internal-coordinate privacy, automatic-IP lookup deduplication and fallback/pagination behavior. Physical phone-camera interaction and production proxy headers must still be checked on the deployment device; local multipart image tests verify the storage path rather than real camera hardware.
