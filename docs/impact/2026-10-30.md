## Directory counts and outcome boundaries

The [network page](https://bloodnet.live/network) and [public statistics endpoint](https://bloodnet.live/api/public/platform-stats) expose current coverage. Use the endpoint's **`data.publicNetwork`** object, including `countDefinitions`, `publicCountingPolicy`, `generatedAt` and `lastUpdated`, when recording a snapshot. Do not treat other administrator-maintained platform counters as verified clinical outcomes.

| Measure | Meaning in the current source implementation |
| --- | --- |
| Total registered accounts | All platform accounts, including inactive accounts |
| Active registered accounts | Registered accounts currently marked active donors |
| Manual donor entries | Active manually maintained individual listings; not registered accounts |
| Community listings | Active organisation/community source listings; not a count of individuals |
| Total listing count | Active registered, manual and community source records counted once per source record |
| Active cities | Recorded country/city coverage pairs, not an unduplicated donor count |
| Organ entries / verified requests | Recorded pledges/listings or administratively verified requests; not completed transplants |

“Once per source record” is not a claim of deduplication across all people and sources. A person serving several cities can appear in several location totals. No live snapshot was fetched for this documentation change; the statistics handler can initialize platform settings if absent. Do not invent a current count from an old UI fixture.

## Outcomes and partnerships

**Completed donations, lives saved, independently corroborated outcomes and formal partnerships are not established by the supplied evidence.** This means unverified, not necessarily zero.

Keep these stages separate:

- **Reported donor contact:** a consenting participant says BloodNet helped them contact a donor. This is not a donation.
- **Reported donation:** a consenting participant reports a completed donation. This is self-report, not independent corroboration.
- **Independently corroborated donation:** an authorized independent source confirms a donation, with appropriate permission and a recorded review. This still does not establish a life saved or sole attribution to BloodNet.

Stages can refer to the same event; do not sum them as separate successful outcomes. Separate blood donation from organ pledges, requests and transplant-related reports. Do not publish identifying case details or small geographic breakdowns that could identify participants.

## Evidence collection workflow

1. Assign a maintainer to collect monthly analytics with exact dates/filters and record exclusion limitations using the [monthly template](templates/monthly-report.md).
2. Use the [outcome template](templates/outcome-record.md) only with voluntary participants through a restricted channel. Explain the collection purpose and obtain separate permission for any public story or identifiable quotation.
3. Have a reviewer check source, event duplication and consent before moving an outcome to corroborated status. Collect the minimum non-clinical confirmation; do not request medical reports as proof.
4. Use the [partnership template](templates/partnership-record.md) to distinguish an outreach lead, informal collaboration and a confirmed agreement. Publish a name/logo only with approval.
5. Publish approved aggregate results, limitations and correction dates. Retain private evidence outside Git under documented access and retention decisions. Re-check consent before publishing any case study.

There is no new in-app outcome tracker in this documentation release. The [roadmap](../../ROADMAP.md) and [support request](../CODEX_SUPPORT_REQUEST.md) describe the maintenance direction; future verified evidence should update this baseline rather than rewrite its historical figures.
